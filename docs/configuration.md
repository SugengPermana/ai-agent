# ⚙️ Configuration Guide

This guide explains how to connect **Google Gemini** to Hermes Agent using an API key generated through **Google AI Studio**.

The configuration flow is:

```text
Google AI Studio
      │
      │ API Key
      ▼
Hermes Agent
      │
      │ Gemini API
      ▼
Google Gemini
```

---

# 1. Create a Google AI Studio API Key

Open Google AI Studio:

https://aistudio.google.com/

Sign in using your Google account.

Navigate to the API key section:

https://aistudio.google.com/apikey

Create a new API key.

Copy the generated key and keep it somewhere secure.

> ⚠️ Never publish your API key or commit it to GitHub.

---

# 2. Configure the Gemini API Key

Hermes needs access to the Gemini API key in order to communicate with Google Gemini.

Open the Hermes environment file:

```bash
nano ~/.hermes/.env
```

Add your API key:

```env
GOOGLE_API_KEY=your_google_ai_studio_api_key
```

Example:

```env
GOOGLE_API_KEY=AIzaSyxxxxxxxxxxxxxxxxxxxxxxxx
```

Save the file.

---

# 3. Verify the Environment Variable

You can verify that the variable exists with:

```bash
echo $GOOGLE_API_KEY
```

However, avoid displaying or sharing the actual API key in screenshots or logs.

For a safer check, use:

```bash
if [ -n "$GOOGLE_API_KEY" ]; then
  echo "GOOGLE_API_KEY is configured"
else
  echo "GOOGLE_API_KEY is not configured"
fi
```

---

# 4. Configure the Gemini Provider

Hermes supports Google Gemini as a model provider.

Run:

```bash
hermes model
```

Select the Google Gemini / Google AI Studio provider.

The exact options may vary depending on the installed Hermes version.

---

# 5. Select a Gemini Model

After selecting the Gemini provider, choose an available Gemini model.

For example:

```text
gemini-3-flash-preview
```

The available model names can change over time.

Therefore, avoid assuming that an older model name will always remain available.

Use:

```bash
hermes model
```

to see the models currently available to your Hermes installation.

---

# 6. Configure the Default Model

Hermes stores its configuration under:

```text
~/.hermes/
```

The main configuration file is:

```text
~/.hermes/config.yaml
```

You can inspect it using:

```bash
cat ~/.hermes/config.yaml
```

Or edit it with:

```bash
nano ~/.hermes/config.yaml
```

Depending on your Hermes version, the configuration may contain model information similar to:

```yaml
model:
  provider: gemini
  default: gemini-3-flash-preview
```

The exact structure may differ depending on the Hermes version.

> Always prefer the configuration format generated by your installed Hermes version rather than copying configuration from an older version.

---

# 7. Configure the Working Directory

If you want Hermes to operate from a specific project directory, configure the terminal working directory.

For example:

```yaml
terminal:
  cwd: /mnt/c/project/ai-agent
```

For WSL, Windows drives are mounted under:

```text
/mnt/
```

For example:

```text
C:\project\ai-agent
```

becomes:

```text
/mnt/c/project/ai-agent
```

You can verify the directory:

```bash
ls /mnt/c/project/ai-agent
```

---

# 8. Test Gemini Through Hermes

Start Hermes:

```bash
hermes
```

Send a simple prompt:

```text
Hello. Introduce yourself.
```

If Hermes responds successfully, the Gemini provider is working.

You can then test a more specific prompt:

```text
Explain what an AI agent is in simple terms.
```

---

# 9. Run Hermes Diagnostics

Run:

```bash
hermes doctor
```

This can help identify problems with:

* Environment variables
* Model configuration
* Provider configuration
* Hermes installation
* Runtime environment

---

# 10. Common Gemini Errors

## Model Not Found

You may encounter an error similar to:

```text
404
Model not found
```

This usually means the configured model identifier is unavailable or incorrect.

Check the available models:

```bash
hermes model
```

Then select a currently available Gemini model.

---

## API Key Error

If Hermes cannot authenticate with Google Gemini, check that your API key exists.

```bash
if [ -n "$GOOGLE_API_KEY" ]; then
  echo "API key configured"
else
  echo "API key missing"
fi
```

Make sure the variable is named correctly:

```env
GOOGLE_API_KEY=your_google_ai_studio_api_key
```

---

## Invalid API Key

If Google rejects the key:

1. Open Google AI Studio.
2. Verify the API key is still active.
3. Create a new key if necessary.
4. Update the Hermes environment configuration.
5. Restart Hermes.

---

# 11. Restart Hermes After Configuration Changes

After changing configuration, restart Hermes.

If Hermes is running interactively, exit it and start again:

```bash
hermes
```

If the Telegram gateway is running, restart it as well:

```bash
hermes gateway restart
```

If `restart` is unavailable in your installed version, use:

```bash
hermes gateway stop
```

then:

```bash
hermes gateway start
```


# 🔐 Security

Never commit your real API key to GitHub.

Do not put this in your repository:

```env
GOOGLE_API_KEY=AIzaSyxxxxxxxx
```

Instead, provide a template:

```env
GOOGLE_API_KEY=your_google_ai_studio_api_key
```

Your real credentials should remain in your local environment.

Recommended structure:

```text
Local machine:

~/.hermes/.env
        │
        ├── GOOGLE_API_KEY
        ├── TELEGRAM_BOT_TOKEN
        └── TELEGRAM_ALLOWED_USERS

GitHub:

.env.example
        │
        ├── GOOGLE_API_KEY=your_google_ai_studio_api_key
        ├── TELEGRAM_BOT_TOKEN=your_telegram_bot_token
        └── TELEGRAM_ALLOWED_USERS=your_telegram_user_id
```
